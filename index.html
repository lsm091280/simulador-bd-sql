Simulador de bases de datos

Una base de datos guarda información organizada en tablas. Con el lenguaje SQL le haces preguntas (consultas) y ella te responde con una tabla de resultados. Elige una base de datos, escribe una consulta y pulsa Ejecutar.

Práctica libre: prueba lo que quieras. Puedes escribir consultas SELECT, sentencias de manipulación INSERT, UPDATE, DELETE, o diseñar tu propia estructura con CREATE TABLE, ALTER TABLE y DROP TABLE. Los cambios solo existen en la memoria de tu navegador durante esta sesión: pulsa «Restaurar datos originales» si deseas volver al estado inicial.

Guía rápida de diseño y DDL (2º Bachillerato)

El lenguaje DDL (Data Definition Language) permite definir y alterar la estructura de las bases de datos (crear, modificar y borrar tablas). Aprende los conceptos y pulsa «Cargar en editor» para probar cada ejemplo.

1. Base de datos, tablas, filas y columnas

Una base de datos es un almacén estructurado de datos. La información se divide en tablas temáticas (ej: alumnos, asignaturas). Cada fila (registro) representa un elemento concreto y cada columna (campo) representa una propiedad de un tipo determinado:

  • INTEGER: Números enteros (ej: 1, 42, -5).
  • TEXT: Cadenas de caracteres o texto (ej: 'Ana', '2º Bach').
  • REAL: Números decimales (ej: 8.75, 3.14).
  • BOOLEAN: Valores de verdad (TRUE o FALSE).

2. Clave primaria (PRIMARY KEY)

Es la columna que identifica de manera única a cada fila de la tabla. Sus valores nunca pueden repetirse ni ser nulos (NULL). Habitualmente se llama id.

CREATE TABLE cursos (
  id INTEGER PRIMARY KEY,
  nombre TEXT NOT NULL
);

3. Clave foránea (FOREIGN KEY) y Relación 1 a N

Una clave foránea es una columna en una tabla hija que guarda la clave primaria de una tabla padre, estableciendo una relación entre ambas. En una relación 1 a N, un registro padre puede tener muchos registros hijos (un alumno tiene muchas notas), pero cada registro hijo pertenece a un único padre.

CREATE TABLE notas (
  id INTEGER PRIMARY KEY,
  alumno_id INTEGER,
  asignatura TEXT,
  nota REAL,
  FOREIGN KEY (alumno_id) REFERENCES alumnos(id)
);

4. ALTER TABLE: modificar estructura

Sirve para alterar la estructura de una tabla existente sin perder sus datos:

  • ADD COLUMN: añade una nueva columna (con valor NULL por defecto para las filas previas).
  • DROP COLUMN: elimina una columna (solo si no es PK ni forma parte de una FK).
-- Añadir columna de correo electrónico
ALTER TABLE alumnos ADD COLUMN email TEXT;

-- Eliminar la columna añadida
ALTER TABLE alumnos DROP COLUMN email;

5. DROP TABLE: borrar tablas

Elimina por completo una tabla y todos los registros que contiene:

DROP TABLE test;

¡Ojo! No podrás eliminar una tabla padre si existen otras tablas con claves foráneas apuntando hacia ella.

6. INSERT, UPDATE y DELETE (DML)

Una vez definida la estructura con DDL, gestionamos sus registros:

-- Insertar un alumno
INSERT INTO alumnos (id, nombre, apellidos, curso, grupo)
VALUES (31, 'Marcos', 'Pérez Gil', '2º Bach', 'A');

-- Modificar datos
UPDATE alumnos SET grupo = 'B' WHERE id = 31;

-- Borrar datos
DELETE FROM alumnos WHERE id = 31;

7. Integridad referencial (Regla de oro)

La integridad referencial garantiza que las relaciones entre tablas siempre sean coherentes:

  • Al insertar/modificar un hijo: el valor de su FOREIGN KEY debe existir en la tabla padre (no puede haber registros huérfanos).
  • Al borrar/modificar un padre: no se permite eliminar una fila padre si aún existen filas hijas que la referencian.
  • Al borrar una tabla (DROP TABLE): debes borrar primero las tablas hijas antes que la tabla padre.

El simulador comprueba estas reglas y emitirá un mensaje explicativo si intentas violar la integridad.

         Conceptos clave
        
    
          
    Tabla
    
          
    Conjunto de datos sobre un mismo tema, organizado en filas y columnas, como una hoja de cálculo. Ejemplo: alumnos.
    
          
    Fila (registro)
    
          
    Cada elemento guardado en la tabla. Una fila de alumnos es un alumno concreto.
    
          
    Columna (campo)
    
          
    Una característica que tienen todas las filas, con un tipo de dato (número, texto, fecha…). Ejemplo: nombre.
    
          
    Clave primaria (PK)
    
          
    Columna cuyo valor identifica cada fila de forma única y nunca se repite. Normalmente es id.
    
          
    Clave foránea (FK)
    
          
    Columna que guarda la clave primaria de otra tabla y sirve para relacionarlas. notas.alumno_id apunta a alumnos.id.
    
          
    JOIN
    
          
    Une filas de dos tablas cuando coinciden la clave foránea y la primaria: FROM alumnos a JOIN notas n ON a.id = n.alumno_id. LEFT JOIN conserva también las filas sin pareja.
    
          
    WHERE
    
          
    Filtra filas: solo se quedan las que cumplen la condición. WHERE grupo = 'A'
    
          
    GROUP BY
    
          
    Agrupa las filas que comparten un valor para poder resumirlas. GROUP BY grupo crea un grupo por cada grupo de clase.
    
          
    Agregación
    
          
    Función que resume varias filas en un valor: COUNT (contar), SUM (sumar), AVG (media), MIN y MAX. Para filtrar por su resultado se usa HAVING.
